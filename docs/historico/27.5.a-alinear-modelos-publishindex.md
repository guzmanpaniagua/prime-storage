Objetivo:

Alinear los modelos de PublishIndex con los utilizados actualmente por el consumidor principal.

Contexto:

El modelo actual de PublishIndexEntry necesita representar exactamente:

{
  packageId,
  filename,
  sha256,
  sizeBytes,
  firstLogicalBlock,
  lastLogicalBlock,
  blockSize,
  blockCount,
  generatorVersion,
  wheelVersion,
  publishedAt,
  products?: {
    strategyVersion,
    taskContractVersion,
    validatorVersion,
    sourcePackageId,
    sourceJobId
  }
}

Problemas detectados:

1. blockSize actualmente se deriva implícitamente del tamaño del rango.
2. products utiliza actualmente:
   - sourceBlockIndex
   - sourcePrimeHash

   pero debe soportar exactamente:

   - strategyVersion
   - taskContractVersion
   - validatorVersion
   - sourcePackageId
   - sourceJobId

Objetivo del cambio:

- No perder ninguna información del modelo anterior.
- Poder reconstruir exactamente un PublishIndexEntry completo.
- Mantener compatibilidad con LocalPublishIndexStore y GithubPublishIndexStore.
- Mantener los tests existentes.

Tareas:

1. Modificar únicamente los tipos y builders de PublishIndex.
2. Permitir blockSize independiente de blockCount.
3. Sustituir el modelo PRODUCTS actual por el descrito arriba.
4. Actualizar buildEntry().
5. Actualizar sameEntry().
6. Actualizar tests.
7. Build y tests verdes.

No tocar rutas.
No tocar GithubArtifactStorage.
No tocar compatibilidad de carpetas.
